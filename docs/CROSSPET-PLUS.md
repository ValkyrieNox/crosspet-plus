# CrossPet Plus 的组成与边界

## 主体与数据流

本版本以 CrossPet 1.3.10 的原生应用为主体。Windows 使用 `app/windows/`，macOS 使用 `app/mac/`；原生宿主负责透明窗口、菜单、设置、前台跟随、接入、额度和多桌宠窗口。`app/web/` 原版页面负责角色姿态、动画、互动、剧情和任务卡片。

新增桥接把 Clawd 接收的会话状态交给 CrossPet 的 `setSessions`、`applyCharState` 与 `applyClientState`，复用其现有逻辑。没有将角色转换成 Clawd 皮肤。

```text
CrossPet 原生程序 ── 原版网页／角色／互动／多桌宠
       │
       ├── 原生 CrossPet hooks 和原版接入工具
       │
       └── Clawd 后台服务 ── 本机／WSL／SSH 代理
                 ├── 会话状态 → CrossPet 原版任务动作和卡片
                 └── 原审批卡片／任务面板／接入与远程设置窗口
```

Clawd 保留两个不可见兼容窗口，用于其内部状态及渲染确认生命周期。新增代码只永久隐藏这两个窗口，审批卡片、Dashboard、设置和其他功能窗口仍使用原窗口类型。

用户入口统一为 CrossPet：一个桌面／开始菜单入口、一个托盘图标、一个开机启动项。任务后台不创建自己的托盘；直接打开内部后台程序会转回原生 CrossPet。任务与审批设置、免打扰也从 CrossPet 菜单进入。关闭 CrossPet 时，其内部后台及 SSH 连接一并退出。

实现上仍有原生 .NET 主进程、WebView2 和 Electron 后台子进程，并非把全部 C# 和 JavaScript 重写到一个进程中；任务管理器会显示这些内部进程。此前版本保留的第二个后台托盘和重复快捷方式属于整合缺口，已在 plus.5 修正。原版多桌宠开关仍可按需产生同一程序内的伙伴窗口。

## 原版功能与新增内容

CrossPet 原有角色／换装、自动跟随、单宠互动、多会话忙碌动作、多桌宠集合和友谊访客逻辑继续使用原实现。原生设置、接入脚本、额度读取、反馈和开发者工具也保留。

新增／适配的代码：

- `app/windows/src/Pet.Clawd.cs`：启动后台、读会话快照、合并原生会话、转发客户端状态、定位审批卡片、退出时停止后台。
- `app/mac/ClawdBridge.swift` 与 `App+Clawd.swift`：Mac 后台宿主锁、实例身份核对、启动期间命令排队、会话合并、按客户端状态分发、多屏审批锚点和退出清理。
- 原生菜单的四个入口，以及启动／轮询／退出处的少量接线。
- `desktop/src/crosspet-service.js`：最小状态快照与本机命令收件箱，用于打开功能窗口、切换任务免打扰、调整锚点、维护已保存的连接和退出。
- `desktop/src/crosspet-model.js`：按上报模型选择 CrossPet 角色。
- Clawd 的服务模式、隐藏兼容窗口、原生启动和组合更新适配。
- 完整构建、校验安装、配置备份与迁移、文档和 CI。

审批协议、权限策略、SSH 身份与部署协议、代理集成和功能窗口来自 Clawd，不是本项目重新实现。新增收件箱没有 allow／deny 操作，不提供绕过审批的入口。

本机同一会话被两套 hook 观察时按原始会话 ID 合并；WSL／SSH 会话按 Clawd 的来源身份区分。小终端使用快照中的限长命令摘要、执行状态和短输出，按工具调用及终端会话匹配结果。命令摘要优先保留主要子命令，包管理器脚本去掉冒号后缀，例如 `npm run build:mac` 显示为 `npm run build`，`git status --short` 显示为 `git status`，并省略重定向和后续参数。命令文本在终端边框内裁剪，短输出经过控制字符清理和常见敏感内容过滤。第二行在运行时显示 `Running...`，结束后优先展示可容纳的真实短输出或 pytest、Jest、Vitest、Node 测试统计，例如 `12 passed`。长输出回退为 `Finished` 或 `Failed`。

## 显示与配置边界

CrossPet 负责实际桌宠的形象、互动、窗口与动作。Clawd 的主题、配饰、大小、漫游／mini 等纯桌宠外观设置不会改变 CrossPet；对应能力使用 CrossPet 自己的界面和实现。Clawd 的会话与审批功能保留自己的设置窗口。

桌宠动作完全采用引入的 CrossPet 1.3.10 原版页面。后台提供会话状态，不按子代理数量改写桌宠动画的优先级：

| 情况 | 角色动作与提示 |
|---|---|
| 一个主任务 | 原版思考、读写、运行等动作；派子任务时沿用 delegating 姿态 |
| 两个主任务 | busy 左右切换，显示主任务卡片 |
| 三个及以上主任务 | swamped 左右切换，显示主任务卡片，超过四张用 +N 表示 |
| 有任务等待回答／授权 | 原版 asking 姿态及等待卡片提示 |

已移除本项目新增的子代理一／二／三数量分档、脉动标记和数量角标，避免覆盖原版多任务动作。主桌宠和按客户端分配的副桌宠使用相同原版页面。Clawd 内部仍按其既有逻辑跟踪子代理生命周期，桌宠不将这份数量转换为额外主任务或动画档位。

权限审批覆盖范围和原生回退继续遵循 Clawd 的 capabilities 和来源规则，不能承诺每个代理、远端和桌面应用都能由桌宠批准。WSL／远端 Codex 在 Auto 模式的限制仍保留；需要 Intercept 时由用户在原设置界面显式选择。

Codex 的自动审核不会额外触发“回到远端审批”的被动提醒。hook 在任务所在的机器上，用当前会话、当前回合的日志核对 `auto_review`；确认后只携带一个用于显示的标记。无法读取、身份不匹配、旧回合、日志正在改写或审核方式不明时，不推测审核者。人工审批、原生 no-decision 回退与权限策略保留原语义，不根据这个标记放行操作。

原生宿主的本机状态快照还提供各已保存 SSH 配置的实际运行状态；配置存在、部署完成和连接成功是三个不同事实。本机连接维护只允许对已保存的 profile 执行原版 Connect／Deploy，继续经过原有控制器、身份校验和传输仲裁；不接受新的目标、任意命令、强制撤销、迁移确认或审批决定。

直接调用任意 API 或网页聊天没有提供 hook／状态事件时无法自动感知。实际模型没有上报时不猜测中转服务的后端。

Remote SSH 每条连接可独立选择自动、IPv4 或 IPv6，应用于连接、探测、部署、SCP 与交互终端。Windows 上 `localhost` 的 IPv6 超时时，WSL 连接可选 IPv4；其他主机仍沿用自己的配置。修改须先断开，并重新部署验证目标；该选项不改全局 SSH 配置，也不绕过主机身份验证。

## 安装、升级与回退

Windows 程序安装在 `%LOCALAPPDATA%\Programs\CrossPet`。CrossPet 数据在 `%LOCALAPPDATA%\CrossPet`，Clawd 设置与既有 SSH 配置仍在 `%APPDATA%\clawd-on-desk` 和 `~/.clawd`。

Mac 的 `CrossPet.app` 内嵌同架构 `CrossPet Plus.app` 后台。原生资源与独立桥接目录位于 `~/Library/Application Support/CrossPet/`，原版 hook 状态仍在 `/tmp/crosspet`。Clawd 配置沿用 `~/Library/Application Support/clawd-on-desk` 和 `~/.clawd`。原版外观设置仅首次导入，已有 Plus 设置优先；不套用 Windows 安装器的配置覆盖迁移。

Mac Plus 使用本 fork 对应架构的完整组合包更新。点击更新后，先下载并校验版本、架构、组合包组件及代码签名，再自动退出、替换并重新启动；新版启动失败时恢复并重新打开旧版。应用所在目录需要可写，无法写入时保留下载页入口。后台不单独升级；独立 Clawd 占用单实例锁时显示后台错误并等待用户重试，不强杀其他进程。

安装器要求旧应用已退出，备份相关配置和自启动项，完整复制并核对文件数量、字节数和每个文件的 SHA-256，再交换安装目录。旧目录保留，已有早期 CrossPet Plus 安装也保留。迁移只把后台主题改为透明兼容主题、关闭自动审批并开启危险操作提醒；其他偏好与远程配置保留。

CrossPet 原生更新器指向本仓库的完整组合包。后台不单独安装 Electron 更新。自动启动复用 CrossPet 自己的 `--ensure` 逻辑，尊重手动退出和“AI 开始工作时自动出现”开关。

账号、PAT、SSH 配置、运行状态和备份均不提交仓库。DSH 的鲸鲸独立运行。

## 平台与确认范围

增强版已接入 Windows 和 macOS 原生桌面，两端都可连接本机与 SSH 代理，Windows 另支持 WSL。Mac 本地构建默认产出本机架构，CI 配置为 arm64 / x64 分别构建；没有增强版 Linux GUI 包。

构建成功与源码保留不能证明所有交互都正常。原版与后台均已成功编译；具体启动、审批和远端确认结果以实际安装记录为准，不把上游的结果算作本项目结果。多桌宠剧情、各代理的审批和各远端环境尚不能宣称全部逐项确认。

Mac 的验证命令、已验证范围与尚需真实代理/远端验证的范围见 [macos-plus.md](macos-plus.md)。
