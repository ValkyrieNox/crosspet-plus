# macOS CrossPet Plus 移植设计

## 目标

将当前 Windows CrossPet Plus 的增强能力接入 macOS 原生 CrossPet：用户启动一个 Mac 应用，即可使用原版桌宠、Clawd 会话与子代理状态、任务面板、审批与等待窗口、本机开发工具接入和 SSH 远程连接。

保留现有角色、换装、互动、多桌宠、额度、原生设置与前台跟随。审批继续由 Clawd 原有能力和策略决定，不扩大任何代理的授权范围。

## 现状与约束

- 原生 Mac 主程序是 `app/mac/` 的 Swift / AppKit / WKWebView，最低 macOS 13。
- Windows 在 `Pet.Clawd.cs` 启动 Electron 服务，通过 `clawd-snapshot.json` 和限定命令收件箱交换状态；后台已有 macOS 平台支持。
- `desktop/src/crosspet-service.js` 已有 darwin 状态目录，可共享协议与会话投影，无需另写审批和 SSH 实现。
- Mac 原生程序仍独立读取 `/tmp/crosspet` 的原版 hook；两路观察同一本机会话时必须合并。
- 当前 Mac 更新器指向上游，必须防止 Plus 应用被原版更新包替换。
- WSL 是 Windows 专属能力；Mac 提供本机和 SSH 接入，不伪装提供本机 WSL。
- 现有 Mac 构建只有原生前端，没有 Electron 运行时；本机没有安装仓库的 Node 依赖。

## 方案选择

推荐沿用 Windows 的组合架构：原生 Mac 前端 + 内嵌 Clawd Electron 后台。它直接复用已存在的桥接协议、完整任务面板、审批、终端导航和 SSH 设置，并保留用户现有桌宠体验。

改用 Electron 作为桌宠前端会改变原版窗口和交互；在 Swift 中重写 Clawd 功能会重复实现审批与远程协议。这两条路线都不适合本次移植。

用户已授权按推荐方向直接实现并跳过方案确认。

工程决定：使用专用宿主锁避免重复实例；快照增加 `hostPid`，Mac 只接收自己的后台。保留现有 Clawd 配置，独立 Clawd 占用单实例锁时报告启动失败，不强杀其他进程。首次启动沿用后台默认审批规则。隔离验证使用测试宿主和真实桥接模块，不启动会改写个人 hooks 的完整后台；真实代理和远端审批须另行实际验证。

## 组件与行为

### 原生后台生命周期

增加独立 Swift 桥接模块，负责启动内嵌后台、读取快照、排队发送菜单命令、报告桌宠锚点和退出清理。存储属性放在 `App` 或独立桥接对象，避免 Swift extension 存储属性限制。

启动使用 `Process` 的参数数组，移除 `ELECTRON_RUN_AS_NODE`，传入宿主 PID 与桥接目录。后台缺失或启动失败时记录可理解的错误，原版桌宠继续运行。后台未就绪时保留有界菜单请求，待取得当前实例身份后再发送，避免第一次点击丢失。

只复用仍新鲜且属于当前宿主的后台实例，启动重试有节流；宿主退出后后台退出。避免关闭另一实例或让重复宿主争抢同一后台。状态读取、启动和检查不阻塞主线程。

Plus 组合包使用当前用户 Application Support 下的专用桥接目录；原版 `/tmp/crosspet` hook 目录保持原样。设置、hook 安装和 SSH 配置继续使用现有 Clawd 的存储规则，不迁移或覆盖已有个人配置。

### 会话、角色与多桌宠

将新鲜、已验证 schema 的快照转换为角色会话表，接入现有 `setSessions`、`applyCharState`、`applyClientState` 和 companion 缓存。只接受已知角色及 `current`，保留客户端身份与子代理数量。

本机原版 hook 与后台按原始会话 ID 去重；与 Windows 保持相同的新旧事件优先规则，保留有效子代理计数。远端身份由现有后台协议生成，不在 Swift 中猜测或重新计算。原版会话文件变化时也合并后台状态，避免下次轮询覆盖 Plus 会话。

快照过期或后台重启时清除其会话和回放缓存，恢复原版会话；防止遗留的忙碌状态驱动角色。暂停事件时不播放，恢复后能同步当前状态。终端跟随与多桌宠继续遵守现有用户偏好。

### 菜单与审批窗口

原生右键和菜单栏共享四个新增入口：任务与会话面板、审批与等待、开发工具接入、SSH 远程连接。审批入口可显示待处理数量。窗口均调用 Clawd 已有窗口，不在原生桥接里新增 allow/deny 命令。

锚点将 AppKit 左下原点坐标转换为 Electron 的主显示器左上原点逻辑坐标；测试覆盖副屏、负坐标与不同缩放。由后台原有窗口定位逻辑决定审批气泡布局。

### 构建、启动与更新

新增 Mac Plus 构建脚本和 npm 命令：先准备后台资源、打包对应架构的 Electron 服务，再构建 Swift 前端，将服务嵌入主 `.app`，包含许可证，完成内外签名验证并生成 ZIP。保持 `build:mac:upstream` 可单独构建原版。

原生前端可继续通用构建；Plus 分发按 arm64 / x64 分别内嵌匹配架构的 Electron，避免通用前端掩盖后台架构限制。默认构建本机架构，支持显式选择另一架构。运行时不依赖用户另装 Node 或 Electron。

`npm start` 在 macOS 打开本地构建的组合应用。新增 Mac CI 构建与架构验证，不自动发布 Release，也不安装覆盖 `/Applications` 内已有应用。

Plus 更新只识别本 fork 对应架构的组合包；在尚未提供经过验证的组合安装器前，更新入口打开本 fork 下载页，不执行上游 `get.sh`。原版构建保留原版更新行为。

## 验证与交付

- Swift 纯逻辑测试：快照解析、过期/实例切换、会话去重、子代理计数、暂停恢复、命令实例与时效、坐标转换。
- 后台协议测试：宿主退出、收件箱动作白名单、菜单功能回调、快照与 SSH 状态；复用现有测试并补充必要用例。
- 保留原版前端回归测试，编译 arm64 与 x64 原生程序，验证组合包结构、签名和匹配架构。
- 在隔离配置下运行本机 smoke test，检查后台心跳、菜单窗口与正常退出，不修改用户现有 hooks、SSH 目标或审批配置。
- 明确区分自动测试、编译成功与实际 GUI 验证；无可用真实远端或代理时列出未验证场景。
- 交付源代码、构建命令和本机架构 Mac 组合包，更新 README 与平台支持说明。

## 非本次范围

不实现本机 WSL，不更换角色素材，不重写 Clawd 审批策略，不发布到 GitHub，不配置 Apple 付费开发者证书或公证，不自动安装或替换用户现有应用。
